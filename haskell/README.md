# A constructive companion to the Lean development

`theorem1` takes a nonconstant `f ∈ ℤ[X]` and returns a pair `(g, H)` with
`H ∣ g'` and `H² ∣ f ∘ g`. Everything is exact integer arithmetic.

```
ghc -O2 -o crit Main.hs && ./crit 1 0 1        # f = X^2 + 1
./crit --demo                                  # the test vectors of spec §8
```

No dependencies beyond `base`.

Run the mirror with `python3 reference.py --demo`, or

## Is the proof constructive?

The content is; the Lean *terms* are not executable. Exactly two steps of the
Lean development invoke a pure existence lemma, and they are the only two steps
this program has to supply an algorithm for:

| Lean | non-computable because | here |
|---|---|---|
| `setup_exists` | `WfDvdMonoid.exists_irreducible_factor` | `Factor.chooseFactor` |
| `exists_bezout` | `IsLocalization.integerNormalization`, and destructuring `IsCoprime` | `Bezout.bezout` |

Everything downstream is closed form. `coeff_scale` *gives* the coefficients of
`H` as `h_j ρ^j h₀^{j-1}`; `W` and `g` are formulas; and Lemmas A–E and the
descent of §4 are proofs carrying no data at all — they justify the output, they
do not compute it. So the program is short, and its only real work is factoring.

## Structure

The modules track the Lean files, and the entry points track the theorems.

| Lean | Haskell |
|---|---|
| `Basic.lean` — `scale`, `coeff_scale` | `Poly.hs` — `scaleX` |
| `Setup.lean` — `structure Setup` | `Construct.hs` — `data Setup` |
| `Exists.lean` — `exists_bezout` | `Bezout.hs`, `QPoly.hs` |
| `Exists.lean` — the choice of `h` | `Factor.hs` |
| `Exists.lean` — `setup_of_factor`, `setup_exists` | `Construct.hs` |
| `Main.lean` — `main_strong` | `Construct.theorem1` |
| `Ledger.lean` | `Verify.hs`, and `--demo` |

`Setup` is Lean's structure with the propositional fields erased — which is what
a record *is*. Those fields are not lost: `Verify.checks` puts every one of them
back as a runtime test, alongside the conclusions of Lemmas A, B, D, E and
Corollary C'. Running the program on an input therefore re-establishes, for that
input, exactly the hypotheses the proof assumes and the conclusions it draws.

Two implementation notes where the Lean proof made the choice for us:

* **`scaleX` is `coeff_scale`.** In Lean `scale M` is
  `Polynomial.compRingHom (C M * X)` and `coeff_scale` is a theorem about it.
  Here the theorem is the implementation: multiply the `j`-th coefficient by `Mʲ`.
  Coefficients grow like `ρ^j h₀^{j-1}`, so `Integer` is not optional.

* **Bézout is extended Euclid over `ℚ[X]`, not the resultant.** This mirrors the
  Lean proof (coprimality in the PID `ℚ[X]`, then clear denominators), and §10
  licenses it: any nonzero element of `(h, h') ∩ ℤ` will do. Dividing out the
  content afterwards is what returns `ρ = 2` for `X² + 1`, where the resultant
  is `4`.

## The two strategies

`H ∣ g'` and `H² ∣ f ∘ g` need only that `h` is primitive, nonconstant, has
`h(0) ≠ 0`, and is squarefree (so that `gcd(h, h') = 1` and the Bézout data
exists). Irreducibility of `h` is used in exactly one place, Lemma D, to conclude
that `H` is irreducible — the Lean proofs of §3 and §4 never mention `hirr`. So:

* `--squarefree` takes `h = primPart(f / gcd(f, f'))` with the `X`-part removed.
  Cheap, and still gives both divisibilities.
* the default runs Kronecker's method to get an irreducible `h`, and so gives
  Theorem 1 as stated. This is the only super-polynomial step in the program;
  a serious implementation would swap in Zassenhaus or van Hoeij.

## An erratum in §8.5 of the spec

The spec says the construction runs on `f = X³ − X² − 2X − 8` (Dedekind's
non-monogenic cubic) "unchanged with `M = 4024`". That value is not attainable.

`M = ρ h₀` with `h₀ = −8`, so `M = 4024` needs `ρ = −503`. But the elimination
ideal `(h, h') ∩ ℤ` is generated by `1006`, not `503`: with
`deg u < 2` and `deg v < 3` — which is without loss of generality, dividing `u`
by `h'` with remainder — the four conditions killing the coefficients of
`X¹ … X⁴` have a one-dimensional kernel, spanned by

```
u = 125 − 21X,   v = 3 − 44X + 7X²,   u·h + v·h' = −1006.
```

Every Bézout constant is therefore a multiple of `1006`, and the smallest `|M|`
the construction can produce is `8048`. `503` is the discriminant of the field;
`disc(h) = −2012` and the index is `2`, and it is the reduced resultant `1006`,
not `disc(K)`, that controls `ρ`.

Nothing else in the spec is affected — §8.5 is a remark that the construction
goes through, and it does; only the constant is wrong. Every other test vector
(§8.1–§8.4) reproduces exactly, including §8.4's parenthetical that the
construction gives `M = 23` and a sextic for `X³ − X − 1`.
